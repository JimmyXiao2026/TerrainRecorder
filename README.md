# 地形记录器 · Terrain Recorder

[简体中文](README.md) | [English](README.en.md)

![icon](src/main/resources/assets/terrainrecorder/icon.png)

Minecraft Java 版 **1.21.11** 的 Fabric **纯客户端**模组：把地形保存成"快照"，之后边走边扩充 / 修正这张地形图，并用**可以穿墙的红色方框**实时标出与快照不一致的方块。

- 只读取客户端内存里**已经加载**的区块，不发送任何自定义网络包
- 服务器**不需要**安装，也不需要 OP；单人 / 多人服务器都能用（含各类小游戏服）
- 数据全部保存在本地，快照是纯文本，可备份、可手工编辑、可压缩分享
- 内置 **英文 / 简体中文 / 繁体中文**，相近语言自动归组（英式英语、繁中香港等）

## 功能一览

| 功能 | 命令 | 说明 |
| --- | --- | --- |
| 拍摄快照 | `/rec` `/rc` | 把当前已加载区块的地形存成带时间戳的快照文件 |
| 扩充地形图 | `/recmode add` `/rcm a` | 自动对齐一张旧快照，边走边把"新出现的方块"加进去（蓝框标出） |
| 修正地形图 | `/recmode min` `/rcm m` | 自动对齐一张旧快照，边走边把"已经消失的方块"删掉（被删的方块蓝框标出） |
| 结束修正 | `/recmode stop` `/rcm s` | 把结果写回基准快照 |
| 差异查找 | `/find` `/fd` | 自动匹配最贴合的快照，实时红框标出"世界里有、快照里没有 / 方块不同"的位置 |
| 指定快照比对 | `/find <id>` | 与指定的某一张快照比对 |
| 关闭高亮 | `/find off` | 结束查找模式 |
| 删除快照 | `/delrec` | 按 id 删除、全部删除、或只保留某一张 |
| 导出 | `/rec export` `/rcex` | 把快照打包成 zip（可跨服务器） |
| 导入 | `/rec import` `/rcim` | 从 zip 恢复快照，冲突逐个确认 |
| 在线下载 | `/rec download import <url>` | 后台下载 zip → 导入 → 自动删除压缩包 |
| 快捷键 | — | 5 个可在选项中改键的操作 |
| 多语言 | — | 英文 / 简中 / 繁中（含地区变体归组） |

所有命令都是**客户端命令**，在本机执行，不会发到服务器。

## 安装

1. 用官方启动器或第三方启动器安装 **Fabric Loader ≥ 0.19.5**（对应 1.21.11）。
2. 把以下两个 jar 放进 `.minecraft/mods/`：
   - `fabric-api-0.141.6+1.21.11.jar`（或更新的 1.21.11 版本）
   - `terrainrecorder-1.0.0.jar`
3. 启动客户端。进入任意世界后聊天栏输入 `/recmode` 或 `/find` 即可确认已加载。

## 快捷键

默认键位可在 **选项 → 控制 → 按键绑定 → 地形记录器** 中修改（分类名会跟随客户端语言）：

| 默认键 | 功能 | 等价命令 |
| --- | --- | --- |

## 命令参考

### `/rec` · `/rc` —— 拍摄快照

```
/rec
```

把**当前已加载的全部区块**里的非空气方块存成 `snapshot_<年月日_时分秒>.snap`，保存在当前服务器（或当前单人存档）的快照目录里，并在聊天栏给出可点击的文件名（点击可在文件管理器中定位）。

- 拍摄范围取决于当前渲染 / 加载范围：**站的位置不同、视距不同，快照覆盖的范围也不同**。
- 写入是先写 `.tmp` 再原子替换，保存过程被中断不会破坏旧快照。
- 同一秒内重复拍摄会自动加 `_2`、`_3` 后缀，不会互相覆盖。

### `/recmode` · `/rcm` —— 扩充 / 修正地形图

```
/recmode              显示帮助
/recmode add   (/a)   扩充：把地形图里没有的方块加进去
/recmode min   (/m)   修正：把地形图里已经消失的方块删掉
/recmode stop  (/s)   结束并把结果写回基准快照
```

启动时会自动在快照目录中挑一张与脚下地形最贴合的旧快照作为基准（规则见 [工作原理](#工作原理)），然后：

- **add**：新扫描到的、地形图里没有的方块会被加入，并临时用**蓝色方框**标出；本次加入的方块如果随后被挖掉，会从地形图里一并撤销。
- **min**：地形图里有、但世界里已经变成空气或变成其它方块的，会从地形图里删除，并临时用**蓝色方框**标出；如果方块又被放回来，会撤销这条移除记录。
- **stop**：把内存里的地形图写回**基准快照文件**（覆盖原文件，没有副本）；如果启动时没找到可对齐的快照，则新建一个带时间戳的快照。

> ⚠️ `stop` 会**直接覆盖**基准快照。重要地形建议先 `/rec export` 备份一份。

### `/find` · `/fd` —— 差异查找

```
/find          自动挑一张最贴合的快照进行比对
/find <id>     与指定快照比对（id 可 Tab 补全）
/find off      关闭红框
```

差异定义：**当前世界里存在、但快照里没有（或同位置方块 ID 不同）**的方块 → **红色方框**（无深度测试，可穿透地形看到）。

- 方框锚定在世界坐标上，走远也能看到轮廓。
- 只显示"多出来的方块"；快照里有、世界已经挖掉的方块**不会**显示。
- **只比对快照真正覆盖到的区块**：快照没记录过的区域不会被当成"全是新增"，避免整片区域标红。
- 持续游玩时，新加载的区块如果**不在快照覆盖范围内，直接跳过**（不扫描、不渲染、也不处理其中的方块变化）。
- 打开 `/find` 时只做三件轻量的事：稀疏采样（±4 区块、每轴 1/4）用于对齐、读取快照（固定格式走快速解析，约 3~4 倍），以及用加载时顺手建好的区块索引算覆盖范围；不会再遍历整片区域。
- **红框分段出现**：每帧最多新增约 100 个框，约 0.1 秒内涨到上限，避免开局第一帧突然写几百个框造成卡顿。
- 每帧最多绘制 800 个方框，超过部分当帧不画（密集差异时优先保证帧率）。
- 只有距玩家 **≤ 10 区块（约 160 格）**的方块会参与绘制与扫描。
- 开启后会**由近到远**分帧扫描（动作栏显示剩余区块），扫完就不再产生额外开销；之后别人挖/放方块会实时增删方框。
- **差异超过 5000 个会自动停止高亮**并提示——通常意味着快照没有覆盖当前位置（或在别处拍的），此时用 `/rec` 重新记录更实际。
- 密集时最多绘制 800 个方框；**画哪 800 个只取决于方块位置，与视角无关**（屏幕外的框交给 GPU 裁剪），所以转动视角不会让色块换一批/忽隐忽现。
- 只有距玩家 **≤ 10 区块（约 160 格）**的方块会参与绘制与扫描。
- 开启后会**由近到远**分帧扫描（动作栏显示剩余区块），扫完就不再产生额外开销；之后别人挖/放方块会实时增删方框。
- **差异超过 5000 个会自动停止高亮**并提示——通常意味着快照没有覆盖当前位置（或在别处拍的），此时用 `/rec` 重新记录更实际。
- 指定快照时，如果当前位置附近完全没有该快照的数据，会直接提示无法比对，而不是满屏红框。
- 当玩家所在区块及相邻一圈都不在快照覆盖范围内时，连续 3 次检测（约 6 秒）后自动结束 `/find`（例如被传送走、退回大厅）。

### `/delrec` —— 删除快照

```
/delrec                  显示帮助
/delrec <id>             删除指定快照（id 可 Tab 补全）
/delrec all              删除当前服务器目录下的全部快照
/delrec all else <keep>  只保留 keep（快照 id，或 latest = 最后修改的那张）
```

> 只有真正删除成功后才会关闭正在运行的 `/find`，输错 id 不会影响当前查找模式。

### `/rec export` · `/rcex` —— 导出

```
/rec export                     显示帮助
/rec export -a                  导出本服务器的全部快照
/rec export <id> [<id> ...]     导出指定快照（可多个，自动去重）
/rec export <id...> -o <名称>   指定压缩包名称
/rec export -a-f                导出"所有服务器"的全部快照（跳过 zips 目录）
```

- 压缩包默认保存在 `<terrain_snapshots>/zips/snapshot_<时间戳>.zip`；`-o 名称` 可自定义（自动补 `.zip`，非法字符会替换成 `_`）。
- 明确写了但找不到的 id 会直接报错，**不会**退化成"导出全部"。
- zip 内部结构为 `<服务器标识>/<文件名>.snap`，因此一个包可以同时装多个服务器的快照。
- 导出完成后聊天栏会出现可点击的文件名，点击在系统文件管理器中定位。

### `/rec import` · `/rcim` —— 导入

```
/rec import                  显示帮助
/rcim -x <zip路径>           导入 zips 目录下的压缩包（路径相对 zips，可 Tab 补全）
/rcim -x                     不带路径 → 弹"打开文件"对话框选择 zip
/rcim -x <zip> -f            遇到同名文件直接覆盖
```

- zip 里只处理 `.snap`，其它文件自动忽略并提示数量。
- 不加 `-f` 时，同名文件会在聊天栏逐个给出可点击按钮：**覆盖 / 跳过**，以及 **全部覆盖剩余 / 取消全部**。
- 路径校验会拒绝越界（最多允许一级 `..` 回到 `terrain_snapshots/`），写入前还会再确认最终路径没有跑出快照根目录。

### `/rec download import <url>` —— 在线下载并导入

```
/rec download import https://example.com/pack.zip
/rec download import jx-bjd-dmm        # 内置快捷源
/rec -d -i <url>                       # 同上，更短的写法
```

下载到 `zips/` 目录 → 走导入流程 → 安装完自动删除压缩包（若有冲突，等确认完成后再删）。

- 下载在**后台线程**进行（带连接 / 读取超时、512 MB 体积上限），网络慢不会卡住画面。

## 多语言

聊天栏提示、帮助文本、按钮文字都走多语言表；按键名走原版语言文件。**相近语言会归到同一份文本**，不需要为每个地区维护一份翻译。

| 语言分组 | 匹配到的客户端语言 | 语言文件 |
| --- | --- | --- |
| 英文 | `en_*`（en_us、en_gb 英式、en_au、en_ca、en_nz…） | `en_us.json` |
| 简体中文 | `zh_cn`、`zh_sg`、`zh_hans_*` 及其它 `zh_*` | `zh_cn.json` |
| 繁体中文 | `zh_tw`（台湾）、`zh_hk`（香港）、`zh_mo`（澳门）、`zh_hant_*` | `zh_tw.json` |
| 其它语言 | 所有未列出的语言 | 回退到 `en_us.json` |

- 归组规则集中在 `Lang.group(String)` 一个方法里，想调整分组只改这里。
- 语言文件在 `src/main/resources/assets/terrainrecorder/lang/`，格式与 Minecraft 语言文件一致（`"键": "文本"`），支持 `%s` / `%d` 占位符。
- 新增一种语言：复制一份 `en_us.json`，翻译成目标语言，命名为语言代码（如 `ja_jp.json`），再在 `Lang.group` 里把该代码映射到语言文件名（例如让 `group("ja_jp")` 返回 `ja_jp`）即可。
- 翻译缺失时逐条回退到英文，不会显示成原始的键名。

当前内置：

| 语言 | 按键名 | 聊天提示 / 帮助 |
| --- | --- | --- |
| English (US/UK/…) | ✅ | ✅ |
| 简体中文 | ✅ | ✅ |
| 繁體中文（台灣 / 香港 / 澳門） | ✅ | ✅ |

## 工作原理

1. **数据来源**：`ClientLevel` 里客户端已经接收、且仍驻留在内存中的区块。遍历每个 `LevelChunkSection`，跳过空气方块，只记录 `BuiltInRegistries.BLOCK` 的方块 ID（如 `minecraft:stone`）。
2. **不做网络交互**：不注册任何自定义 payload，也不修改服务端；客户端命令在本地 dispatch。
3. **扫描范围**：以玩家为中心，**水平 ±10 区块（约 160 格）**内扫描；更大的范围不扫描、不渲染。
4. **更新方式（不再周期性全扫）**：
   - **方块变化**：实时增量处理。注入的是 1.21.11 客户端真正应用服务器方块变化的入口
     `ClientLevel.setServerVerifiedBlockState(...)`，以及本地路径 `ClientLevel.setBlock(...)`；
     这样别人挖/放方块会立即反映到差异与地形图里。
   - **区块数据**：区块加载（含服务器重发区块）时触发 `CHUNK_LOAD`，把该区块排进扫描队列。
   - **初始扫描**：模式开始时把范围内的区块**由近到远**入队，每 tick 最多占用 **2.5 ms** 处理；
     动作栏显示"剩余 N 个区块"，队列排空后**不再有任何周期性扫描**。
   - 走进原本在范围外、加载过的区块时，会自动补扫。因为只扫一次 + 增量更新，静止时开销接近 0。
5. **对齐规则**：以玩家为中心取 **31 × 5 × 31** 的区域（水平 ±15、垂直 −2..+2），把区域内"当前世界非空气方块"与某张快照逐位比较（允许整张快照做一次平移对齐）。同 ID 比例 **≥ 80%** 才认为"这是同一片地形"；快照按文件名（时间戳）从新到旧检查，遇到 ≥95% 贴合的最新一张就直接采用，否则取匹配方块数最多的那张。
   - 区域直接从世界读取；平移投票只用玩家附近 ±4 区块、按 4 格步长读取的稀疏样本（读取量约 1/64），所以 `/find` 启动几乎不需要遍历整片区域。
   - 判定"需要多少重叠才认可平移"的阈值随快照 / 采样规模自适应（约 8~100 块），不会因为一两个巧合方块就把偏移锁死。
6. **差异**：`/find` 比较的是"方块 ID"，同 ID 不同状态（朝向、含水、半砖上下等）视为相同；方块 ID 变了视为差异。
   - 只比对**快照覆盖到的区块**（快照拍摄时加载过的区块，按对齐偏移换算），没覆盖的区域视为"未知"，不参与比对。
   - 单次 `/find` 的差异超过 **5000 个**时自动停止高亮并提示：这通常说明快照与当前位置对不上（在别处拍的、或快照范围比当前视距小）。
   - 每帧最多绘制 **800** 个方框；选哪 800 个只与方块位置有关，与视角无关（屏幕外的框由 GPU 裁剪），转动视角不会让色块忽隐忽现。
7. **离开检测**：`/find` 期间每 2 秒检查一次玩家所在区块及相邻一圈是否在快照覆盖范围内，连续 3 次都不在才自动关闭（被传送走 / 退回大厅时会触发）。

### 性能说明

- 开启 `/find` 只会做**一次**由近到远的扫描（每 tick 最多 2.5 ms），扫完后静止开销接近 0；
  之后别人挖/放方块通过 mixin 实时增删方框，不再有周期性全图扫描。
- 想更快 / 更省可以在源码里调这几个常量：

| 常量 | 位置 | 作用 |
| --- | --- | --- |
| `SCAN_BUDGET_NANOS` | `TerrainManager` | 每 tick 扫描时间预算（默认 2.5 ms） |
| `MAX_HIGHLIGHT` | `TerrainManager` | 差异超过该值自动停止高亮（默认 5000） |
| `MAX_BOXES` | `FindRenderer` | 每帧最多绘制的方框数（默认 800） |
| `RAMP_STEP` | `FindRenderer` | 分段渲染每帧新增的方框数（默认 100） |

## 数据存储

| 内容 | 路径 |
| --- | --- |
| 单人存档 | `<.minecraft>/saves/<存档名>/terrain_snapshots/singleplayer/` |
| 多人服务器 | `<.minecraft>/terrain_snapshots/<服务器地址>/` |
| 导出 / 下载的 zip | `<terrain_snapshots>/zips/` |

- 目录名来自服务器地址（`:`、`/` 等非法字符会替换成 `_`），所以**改服务器地址文字会导致换一个目录**。
- 文件名默认 `snapshot_yyyyMMdd_HHmmss.snap`；**可以直接改成中文 / 英文名**，命令里用改后的名字即可（例如 `/find 城堡`、`/delrec 城堡`）。id 解析顺序是：`snapshot_<名字>.snap` → `<名字>.snap`，排序优先级是"中文名 → 英文自定义名 → 默认 `snapshot_*`"。
- 快照格式为 **NDJSON**（每行一个方块），纯文本、可手工处理：

```json
{"x":100,"y":64,"z":-20,"b":"minecraft:stone"}
{"x":101,"y":64,"z":-20,"b":"minecraft:dirt"}
```

> 一张快照会记录**范围内所有非空气方块**（包括石头、深板岩这类填充方块）。以渲染距离 12 区块为例，一次 `/rec` 可能写入上千万行、文件达到数百 MB，比对时还会整份读入内存。建议：
> - 快照/比对前适当降低渲染距离，或分区域多次拍摄；
> - 给客户端分配更大的堆内存（例如 4 GB 起）；
> - 用 `/rec export` 备份后再做 `recmode` 修改。
>
> 读写都是流式的（一行一行读 / 写，先写 `.tmp` 再原子替换），单行损坏只跳过该行并写日志，不会让命令直接崩掉。
> 读取时本 mod 自己写出的固定格式走**快速解析**（约为 Gson 的 3~4 倍），并在同一遍里记下"哪些区块有数据"，
> `/find` 直接用这个索引判断覆盖范围，不需要再遍历几百万个方块。

## 导入 / 导出 / 在线下载

- **导出**包内结构固定为 `<服务器标识>/<文件名>.snap`，所以：
  - 在 A 服导出的包，在 B 服导入时会**还原到 A 服目录**（不会覆盖 B 服同名文件），可以在 `/find` 补全里看到；
  - 也可把 `zips/` 整个目录拷给别人，对方用 `/rcim -x <文件名>` 导入。
- **导入**只认 `.snap`；同名冲突可逐个决定，`-f` 全部覆盖。
- **移动端 / 无桌面环境**：文件对话框可能不可用，请用 `/rcex -o <名称>` 导出、用 `/rcim -x <zip>` 导入（zip 放在 `zips/` 下）。
- **在线下载**：仅支持 `http://` / `https://`；内置 `jx-bjd-dmm` 快捷源指向项目作者发布的示例包。下载在后台进行，结束后自动接导入流程。

## 限制与注意事项

1. **只看得到客户端已加载的区块**：未加载区域既不会被记录，也不会被比对；走远后再 `recmode` 会补上新区域，但旧区域仍是旧数据。
2. **只记录方块 ID**：不记录方块状态（朝向、含水、生长阶段等）、方块实体（箱子内容、告示牌文本、刷怪笼数据）、实体、光照、生物群系。
3. **不记录维度**：主世界 / 下界 / 末地共用同一个服务器目录，文件名也不含维度；跨维度使用同一批快照时可能对齐到错误的地形。
4. **扫描与渲染硬上限 10 区块**：超过范围的差异不会绘制，`/recmode` 也不会主动扫描。
5. **`/find` 只显示"多出来的"方块**，不显示"快照里有、现在没了"的方块；后者请用 `/recmode min` 修正。
6. **`/recmode stop` 覆盖基准快照**，没有自动备份。
7. **差异判定粒度粗**：同 ID 不同状态视为相同，所以"把楼梯转个方向"不会被当成差异。
8. **客户端命令可能与服务器命令同名**：例如服务器插件也提供 `/find`、`/rec` 时，客户端的同名命令会参与解析，可能拦截本该发给服务器的命令；`/help` 也有同样的名字冲突风险。
9. **文件对话框依赖桌面环境**（Windows / macOS / Linux）；无头环境会提示改用 `-x` / `-o`。

## 从源码构建

需要 **JDK 21**（Gradle 会使用 `JAVA_HOME`），首次构建需联网下载 Minecraft / Fabric 依赖。

```bash
# Windows
gradlew.bat build

# macOS / Linux
./gradlew build
```

产物：`build/libs/terrainrecorder-1.0.0.jar`（另有 `-sources.jar`）。

开发时直接启动客户端：

```bash
gradlew.bat runClient
```

版本号、游戏版本、Fabric API 版本都在 `gradle.properties` 里：

```properties
minecraft_version=1.21.11
loader_version=0.19.5
fabric_api_version=0.141.6+1.21.11
version=1.0.0
```
